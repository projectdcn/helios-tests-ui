Offline installer bundles of the helios-tests web UI. Pick one, unpack it and run `./install.sh`
(see README-INSTALL.txt inside). An upgrade keeps `config/` and `data/`; `bin/install.sh --rollback` goes back.

- `helios-ui-v2026.10.24.tar.gz` - Linux x86_64, CPython 3.10 - 3.12
- `helios-ui-v2026.10.24-macos.tar.gz` - macOS arm64 + x86_64, CPython 3.10 - 3.14
- `SHA256SUMS`

## Test plan: IFCP cases selectable as one group
- **Scope tags:** a Scope cell can now carry several tags separated by `;`, for example `Switch + Compute; IFCP`.
  A filter matches the whole cell or any one tag, so the existing Scope values keep working.
  - Run form: the Scope filter lists each tag, so **IFCP** can be picked on its own.
  - Command line: `tools/select_cases.py --scope IFCP` selects every IFCP case.
  - HTML report: the "By scope" table counts a case under each of its tags.
- **The IFCP tag is on 83 cases:**
  - sessions, keepalive, discovery, CapReq / CapResp / CapSet, frame format and retransmits;
  - SPDM over the IFCP control channel;
  - the ifcp-negotiation and "CP sessions" cases, and HC-012.
  The tagged workbook is `testplan/full_rack_testplan.xlsx` in helios-tests; upload it in the UI to use the tags.
  The installer ships no workbook.
- **`tools/tag_scope.py`:** adds or removes a tag on a list of plan IDs (`testplan/tags/ifcp.txt`). It refuses to
  write while Excel holds the workbook's `~$` lock, writes a dated backup first, and has `--dry-run`.

## SSH
- A malformed line in `~/.ssh/known_hosts` is skipped, as OpenSSH does, and warned about once per run. Before, one
  truncated line (written when the jump host's disk was full) made every switch SSH fail.

## Link check (bundled helios-debug, used by HC-012)
- **Forwarding entries without a switch port:** when SONiC's `show mac` fails on such entries, the check now names
  them and where they came from (added at runtime, configured, or left in the hardware only). It reports this as a
  problem on the switch, not an access error.
- **IFCP cable check:** each GPU port's IFCP peer is compared with the switch port that AFM's description and
  forwarding entry name, so a cable that lands elsewhere is reported as miscabled.
- **VLANs** are read on every switch chip and checked:
  - a GPU-facing port in no VLAN;
  - a port whose VLAN differs from what its chip uses for that GPU port number;
  - a static entry off its port's VLAN;
  - a chip whose VLANs differ from the others'.
- **AFM numbering:** trays and GPUs are shown with their AFM names and numbers: pod-1-0-SwitchTray / ComputeTray,
  GPU0-3 with the acc-id.
- **Expired quarantine:** an inventory quarantine past its `until:` still applies, and the report says it has ended.
