Offline installer bundles of the helios-tests web UI. Pick one, unpack it and run `./install.sh`
(see README-INSTALL.txt inside). An upgrade keeps `config/` and `data/`; `bin/install.sh --rollback` goes back.

- `helios-ui-v2026.10.21.2.tar.gz` - Linux x86_64, CPython 3.10 - 3.12
- `helios-ui-v2026.10.21.2-macos.tar.gz` - macOS arm64 + x86_64, CPython 3.10 - 3.14
- `SHA256SUMS`

## Clearer verdicts when the rack, not the product, is the problem
- **AFM unreachable:** when the AFM API cannot be reached (connection reset, refused or timed out, retried for 60 s),
  the AFM cases are BLOCKED with one line naming the address and what to check. Before, they ERRORed with a long
  `requests` traceback.
- **Switch CLI broken:** a switch whose SONiC CLI refuses every command because of extra network namespaces (for
  example `cni-*` ones left by k3s / Kubernetes pods) makes its cases BLOCKED with one line naming the switch and the
  namespace. Before, each switch FAILed with a traceback. The fake switch can reproduce it (fault `cni_netns`).

## Web UI
- **Default BMC login:** the Inventory tab has one box for the switch BMC user, the compute BMC user and the BMC
  password, with one Save. The users are saved in the inventory (`defaults.switch.bmc_user` /
  `defaults.compute.bmc_user`, comments kept, dated backup); the password goes to the password store only. Nodes
  without their own user or password use the defaults. The status names any node that has no BMC user at all.
- **Setup node table:** a node's own BMC user is shown; an empty field shows the default it uses.
- **Jump-host runs:** an SSH connection the jump host drops before the login is retried after 5, 15 and 30 s.
  Nothing has run at that point, so the retry is safe. A run no longer fails on its first step when the jump host
  throttles new connections.

## Reports
- **Health report:** the CPU usage column of the switch and compute tray tables shows what is available, for example
  "10% busy - available 90% (~14 of 16 CPUs)".
