helios-tests

How to run the Helios rack tests

pytest automation for the AMD Helios full-rack scale-up test plan: 6 SONiC switch trays (2 ASICs each), 18 compute trays (4 GPUs each), with the AFM controller and the IFoE fabric.

Setup Without a rack On a real rack Specific cases Results Coverage

0Setup

Run everything from the repo root. The machine you run from needs SSH access to every switch and compute in the inventory. On a new machine (for example a lab host), create the virtualenv once:

cd ~/dev/helios-tests
python3 -m venv .venv
.venv/bin/pip install -e '.[tools]'

1Without a rack: check the framework

These use recorded SONiC and GPU outputs from selftest/replay, so no hardware is needed.

Unit tests and the 28 injected-fault checks

.venv/bin/pytest unit

The whole suite against the recorded outputs

.venv/bin/pytest tests --inventory selftest/inventory.yaml

Expected: 102 passed 13 skipped. Disruptive tests skip unless you allow them; every skip prints its reason.

Including the disruptive tests (restarts, resets, reboots)

.venv/bin/pytest tests --inventory selftest/inventory.yaml --allow-disruptive

Expected: 111 passed 4 skipped.

2On a real rack

  1. Make your inventory. Files named *.local.yaml are git-ignored. 
    cp inventory/example-fullrack.yaml inventory/rack1.local.yaml
  2. Edit inventory/rack1.local.yaml.
    • Under switches: and computes:, set each host: to the real hostname or IP.
    • Under defaults:, set the SSH user, and either key_file or password_env for each node type.
    • Fill in the VERIFY items: commands.l2ping.cmd, commands.transferbench.in_domain / cross_domain, commands.rccl.cross_domain, commands.perftest.* and commands.ras.*.
    • For the scale-out RDMA cases, add rdma: ports to the two computes named in commands.perftest.nodes. For DC/AC power cycles, add bmc: / pdu_outlet:.
    • Set your pass limits under thresholds:, such as expected_fans, expected_psus, psu_capacity_w and the bandwidth floors.
    Until a VERIFY command is set, the tests that need it skip and name the missing setting. They never guess a command.
  3. Export secrets, if you used password_env: 
    export HELIOS_SWITCH_PASSWORD='yourpassword'
  4. Run. Start small with one switch and two computes: 
    .venv/bin/pytest tests --inventory inventory/rack1.local.yaml --switches sw1 --computes c01,c02 -v
    Then run the full L1 suite: 
    .venv/bin/pytest tests -m l1 --inventory inventory/rack1.local.yaml --log-file=results/run.log

    --log-file records every SSH command, its exit code and how long it took.

Skip passing --inventory every time

export HELIOS_INVENTORY=inventory/rack1.local.yaml

3Running specific cases

What you wantAdd this
Specific plan IDs--tc TC-SWH-002,TC-AFM-001
Part of the rack--switches sw1,sw2 / --computes c01,c02
Switch hardware tests onlytests/l1/test_switch_hw.py
Datapath tests only (ping, TransferBench, RCCL)tests/l1/test_afm_datapath.py
Switch agent / hardware / RDMA / RAS onlytests/switch / tests/hw / tests/scaleout / tests/ras
By level or marker-m l1 / -m "l1 and not stress"
Tests that restart services, reset devices or reboot (TC-SWA-140/141, all RAS)--allow-disruptive
Manual tests (e.g. the TC-SWH-009 heat test)--run-manual

Example: only the PSU checks on two switches

.venv/bin/pytest tests --tc TC-SWH-018,TC-SWH-019,TC-SWH-021 --switches sw1,sw2

4Results

Each run creates a folder results/<rack>-<timestamp>/ with two files:

FileContents
tc_summary.csvOne PASS / FAIL / SKIP / PARTIAL verdict per plan ID.
tc_results.csvOne row per test, with the failure message and measured values such as bandwidth and bus bandwidth.

5Coverage: automated vs. missing

Per-category table

.venv/bin/python tools/coverage.py

Plus every unautomated case, saved to a file

.venv/bin/python tools/coverage.py --missing > results/missing.txt
Column / outputMeaning
automatedHow many of that category's cases have a test (a @pytest.mark.tc tag).
totalHow many cases the plan has in that category.
List after the tableOnly with --missing: every case that has no test yet, with its ID, level and title.
