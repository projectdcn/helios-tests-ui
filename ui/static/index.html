One-time setup a rack needs before tests (Check access verifies these)
  • SSH key on the machine that runs the tests (this UI server, or the jump host for a jump-host rack), with no passphrase, accepted by every switch and compute tray. Install it with ssh-copy-id; the inventory's key_file names it. No switch / compute passwords are used.
  • Network path from that machine to the nodes and to the AFM controller.
  • The rack's inventory (Inventory tab): hosts, users, key_file.
  • Passwordless sudo for the SSH users on switches and computes (NOPASSWD in /etc/sudoers.d/): checks run as sudo -n and never answer a prompt.
  • Compute trays, for traffic cases: GPUs ACTIVE in afmctl, openable by the user (render group, or commands.datapath.sudo: true), not used by another workload; TransferBench and the RCCL tests installed where the inventory says.
  • AFM password: typed below for each run, or saved for this rack - without it the AFM cases skip.
  • Calibration: the inventory's VERIFY items and thresholds; until set, those cases SKIP and name the setting.
  • Special cases only: rdma: ports (scale-out RDMA), bmc: / pdu_outlet: (power cycles), an MCH rack, LDAP / RADIUS servers, upgrade images.

Every run started here joins the rack's current session (the first run starts one, named by date); the session's consolidated result (the latest result of each test across its runs) is at the top of the Results tab.

Presets and the rack's default form are saved per rack in ui-presets.json / ui-defaults.json of the rack's results folder; the form you last used is remembered in this browser. The form opens with the saved default if there is one, else the form last used in this browser, else the original form. The AFM password is in none of them (it can be saved on the UI server - macOS Keychain, or a 0600 password file on Linux - below).
